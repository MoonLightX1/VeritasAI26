1. How the prediction works

It all lives in backend/services/predict.py. When you hit Predict on a stock page, the server does these steps in a background job so the page can show progress.

  1. Get the price history from Yahoo Finance.
  2. Work out the trend and how jumpy the price is, using the last 60 moves. The trend is capped so it cannot run away.
  3. Search the news. Seven searches run at once, get merged and deduped, and the newest 45 headlines are kept. Cached for 15 minutes.
  4. Score every headline from -1 (bad) to +1 (good) with the keyword list.
  5. Context rules fix the dumb stuff. Shows and movies get ignored, executive scandals get forced negative.
  6. If the AI loaded, it re-reads the 16 most important headlines and says good, bad, neutral or not relevant.
  7. Squash it all into one mood number. Newer headlines count more, a small pile gets pulled toward zero, serious stuff gets an extra push down.
  8. Draw the forecast line. The trend fades out, an overextended price gets pulled back toward its average, a little wiggle is added, and the shaded range widens with distance.
  9. If the AI loaded, it also gives its own outlook and percent change. That gets blended 75/25 with the stats line and capped.

Your adapter is a text writer, not a classifier. So the keyword list always does step 4, and the adapter works in steps 6 and 9. If the AI fails anywhere, the app falls back to the plain version and says why. That part works well and is worth keeping.

2. The AI adapter

The AI is a LoRA adapter. That is a small file of changes that sits on top of a normal model, so we did not have to retrain the whole thing.

The context rules

A scary word is not always bad news. A show called "The Affair" is not a scandal. So quoted titles get stripped, movie and trailer headlines get ignored, and a personal scandal only counts if an executive or owner is in the headline.

def judge(title, score):
    """(score, relevant, note) after the context rules."""
    words = set(re.findall(r"[a-z\-]+", strip_titles(title).lower()))
    if words & ENTERTAINMENT and not (words & BUSINESS):
        return 0.0, False, "About a show, film or trailer, not the company's business"
    if personal_scandal(title):
        return min(score, -0.85), True, "Executive scandal"
    return score, True, ""
def personal_scandal(text):
    clean = strip_titles(text)
    return bool(ROLES.search(clean) and PERSONAL.search(clean))

Squashing headlines into one number

def combine(items, scores, now=None):
    # newer headlines count more (about a 4 day half-ish life), and only a few
    # headlines means we are less sure, so the number is pulled toward 0
    now = now or time.time()
    wsum = 0.0
    ssum = 0.0
    severe_w = 0.0
    for it, s in zip(items, scores):
        age_days = max(0.0, (now - it["time"]) / 86400.0)
        w = math.exp(-age_days / 4.0)
        wsum += w
        ssum += w * s
        # an executive scandal / lawsuit / investigation is not cancelled out by ten
        # "stock rises" headlines, so negative ones like that get an extra push of their own
        if s < 0 and is_severe(it["title"]):
            severe_w += w
    if wsum <= 0:
        return 0.0
    base = (ssum / wsum) * (wsum / (wsum + 1.0))
    return max(-1.0, min(1.0, base - min(0.7, 0.3 * severe_w)))

Trend and swing

The forecast needs two numbers from the price history. The trend is the average move per step. The swing is how jumpy the price is. The trend is capped at 1.5 times the swing.

def _vol(points):
    # (trend per step, typical swing per step) from the recent prices, as log returns
    closes = [p["c"] for p in points]
    n = len(closes)
    if n < 8:
        return None
    look = min(60, n - 1)
    rets = [math.log(closes[i] / closes[i - 1]) for i in range(n - look, n) if closes[i - 1] > 0 and closes[i] > 0]
    if len(rets) < 5:
        return None
    mu = sum(rets) / len(rets)
    var = sum((r - mu) ** 2 for r in rets) / (len(rets) - 1)
    sigma = max(math.sqrt(var), 1e-5)
    # a trend alone should not be allowed to run away
    return max(-1.5 * sigma, min(1.5 * sigma, mu)), sigma

The AI double check

The AI re-reads up to 16 headlines and gives each one a verdict. Here is what the code does with each verdict.

if v == "good":
    scores[i], rel[i] = (old_s if old_s >= 0.5 else 0.5), True
elif v == "bad":
    scores[i], rel[i] = (old_s if old_s <= -0.5 else -0.5), True
elif v == "neutral":
    scores[i], rel[i] = 0.0, True
else:
    scores[i], rel[i] = 0.0, False

Blending the AI with the trend

So if the AI says +60 percent on a stock that swings 2 percent a day, the app quietly cuts it to a fraction of that.

5. Test one: can it read a headline?

We wrote 63 headlines by hand in the style of real financial news: 20 good, 20 bad, 15 routine, and 8 that are not about the business at all. We labeled each one ourselves, then ran the keyword scorer and the context rules on them. This is the path with no AI.

8. Test four: the forecast line and shaded range

For this one we made up stocks. Each has 250 days of random daily moves (about 2 percent a day). We ask the real forecast function for 30 days ahead, then generate what "actually" happens and check it. 1,500 stocks per scenario.

Why fake prices? We had no real price history. The good part is we know exactly how the fake world works, so we can tell if the code does what it claims. The bad part is it says nothing about real markets, and we will keep saying that.

What this shows

  • When the fake world acts the way the code assumes (steady jumpiness, independent days), the range does its job. 80.4 percent against 80 promised. That is the win.
  • Across all days it slightly undershoots (76 percent), because the jumpiness is guessed from only 60 past moves.
  • When volatility suddenly jumps, the range catches only about 42 percent while still claiming 80. It only knows the past. Real shocks like earnings surprises and scandals are exactly when people lean on the range most.
  • Direction was right about half the time everywhere, a coin flip. In our fake world the news has no link to prices, so there was nothing to find, and it found nothing. That is not a bug, but it also means this test could never have shown the forecast is good.
  • When we fed in strong news that was pure noise, the average miss got about 28 percent worse than just saying "no change" (10.75 versus 8.40). That is the cost of tilting the line on news that does not matter. In real life news sometimes does matter, and this test cannot say how often.

How to read what comes out:

  • If the adapter row is not higher than the plain Qwen row, the adapter did nothing on this test.
  • If keyword only beats both, the AI check is making things worse and should stay off.
  • Look at the line that counts good called bad or the other way round. That is the worst kind of miss.
  • If lots of AI answers could not be read, the JSON format is the problem, not the headline reading.
  • It shuffles the headlines with a fixed seed. The list is sorted by answer, and 16 good headlines in a row would hint the model.

10. The math behind the claims

Not formal proofs, just the arithmetic, so you can check us.

The 31.7 percent baseline. The biggest group in the headline set has 20 of 63 headlines, and 20 divided by 63 is 31.7 percent. Always guessing that group scores exactly that.

The 77 to 93 percent range is the Wilson 95 percent interval. It is a range for what the real accuracy could be.

# wilson interval, a range for what the real accuracy could be
def wilson(k, n, z=1.96):
    p = k / n
    d = 1 + z * z / n
    centre = (p + z * z / (2 * n)) / d
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / d
    return centre - half, centre + half

lo, hi = wilson(55, 63)
print("55 of 63 ->", round(lo * 100, 1), "to", round(hi * 100, 1))
55 of 63 -> 76.9 to 93.4

Why the range is 1.28 times sigma times the square root of k. If daily moves are independent with standard deviation sigma, the total move over k days has standard deviation sigma times the square root of k. A two-sided 80 percent range uses 1.28. So the formula is exactly right when moves are independent, bell-shaped and the jumpiness stays put. The simulation agrees when those hold (80.4 percent) and falls apart when they do not (41.7 percent).

Why direction near 50 percent is not alarming. With 1,500 trials a coin flip wobbles by about this much:

# with 1500 trials a coin flip wobbles about this much
print(round(math.sqrt(0.5 * 0.5 / 1500) * 100, 2), "percent")
1.29 percent

Our five results were 49.3, 51.6, 49.3, 50.6 and 49.4. All within about 1.3 wobbles of 50, so they look like coin flips, which is what fake data should give.

11. What could be wrong

Seen in our tests

  • Words with two meanings fool the word lists ("fall" the season).
  • A good word and a bad word in one headline cancel, so real bad news can score neutral.
  • "better than expected" slips through because "better" is not on the list.
  • Non-business headlines only get ignored if they contain one of the listed entertainment words.
  • "fined" is not on the serious list, so a regulator fine does not get the extra push down.
  • If the AI's direction and number disagree, the code picks the direction word.
  • The shaded range is far too narrow after a sudden jump in volatility.
  • Tilting the line on news that is not informative makes it worse than "no change".
  • Strong news replaces the trend instead of adding to it, so on a stock already rising fast, good news can lower the forecast a hair.

Spotted in the code, not tested

  • Daily forecasts skip weekends but not market holidays.
  • Duplicates are caught by the first 70 letters of a title, so reworded copies count again.
  • Google results are kept if the title has the company name, so a name like Apple can pull in unrelated stories. Short tickers like F are skipped for that matching.
  • When the AI says good or bad, the strength is set to at least 0.5 in that direction, whatever the earlier score was.
  • News is hours or days old when scored, and the price may have already reacted. The code cannot know.
  • The three data feeds are unofficial and can change or block us any time.

About the adapter

  • Accuracy is not measured yet. Test five is how to fix that.
  • One pass over about 10K lines at a fairly high learning rate (0.0002) is a light touch. It could have learned the answer format and little else, and we cannot tell which until it is tested.
  • The FinGPT set only covers the 30 Dow companies in one year (May 2023 to May 2024). The app lets people pick any stock, so for most other companies the adapter may have seen much less.
  • The training prompts and the app prompts are probably different. The app asks for a verdict per headline and for a JSON outlook. If the training data was written in another style, the adapter may help less than it should. We cannot check, because the training prompt format was not saved with the adapter.
  • Labels written by GPT can be wrong or inconsistent, and the model learns the mistakes too.
  • The headline double check only looks at the top 16 headlines. The other 29 are scored by keywords alone.
  • The AI sees the stats line (the simple trend estimate) inside its prompt, so its answer can lean toward it.

12. What these results would and would not justify

This is the most important section, so we are going to be blunt.

What they would justify

  • Using the tool as a reading aid, to see which headlines look serious and read those first.
  • Using it as a teaching demo of how news and price trend can become a rough picture.
  • Practice trading with pretend money, which is what the app does.

What they would not justify

  • Buying or selling real shares because of the forecast. We never compared it to real prices. We have zero evidence it predicts anything in a real market.
  • Treating headline accuracy as price accuracy. 87 percent on 63 hand-picked headlines says it can roughly read a headline. It does not say prices move the way headlines suggest. Those are two different questions and we only answered the first.
  • Trusting the AI's percent change. The adapter has not been tested.
  • Using the shaded range as a safe limit or stop-loss. It caught about 42 percent in the shock test while claiming 80. It fails exactly when a surprise hits.
  • Believing it beats just holding the stock. We never compared it to buy-and-hold and never counted trading costs or taxes.
  • Deciding how much to invest. A small sample and no real-price testing cannot tell anyone that.

What it would take to justify more

  • Run run5_adapter.py and put the real adapter numbers on this page.
  • A backtest on real historical prices, many stocks, several years, using only headlines that existed at the time.
  • Test on data the code never saw while it was being built, and compare against simple baselines: buy-and-hold, and the price trend alone with no news.
  • Include trading costs, and check the results are bigger than luck.
  • Keep the headlines in the test out of the training data. Ours were hand-written, so they are safe, but a bigger test set from real feeds needs a check.

This is a class project analysis, not financial advice. Nothing on this page is a recommendation to buy or sell anything.
